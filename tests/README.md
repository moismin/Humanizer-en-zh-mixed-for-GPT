# 如何检查改写结果（中英双语保真 & 防 GPT 防御性笑话综合测试）

这组材料检查编辑与回应的事实边界、文体声音与**反 GPT 防御性杠精能力（Group G）**，不检测文章是否由 AI 撰写。

## 文本案例（28 条）

让所使用的 Agent 读取仓库的 `SKILL.md`（或根目录 `AGENTS.md`），再逐条执行 [fixtures/cases.json](fixtures/cases.json) 中的 `request` 与 `input`。分别保存输入和输出；不要把预期改写措辞提供给 Agent。

28 条案例分为两部分：
1. **原中文版 18 条事实保真案例（#1–#18）：** 覆盖缺少数据时不补造指标、保留推测与归因、保留独立列举项、正在与计划、数量/范围/否定、未知施事者、作者样本、引语、同时发生与前置条件、发布顺序与授权条件。
2. **新增 10 条《GPT 防御性笑话大全》专项案例（#19–#28）：**
   - `gpt_joke_01_weather`（天气：太阳真好 vs. 并不意味着明天也有太阳/气候改善）
   - `gpt_joke_02_sleep`（睡觉：睡得真香 vs. 主观睡眠质量不等于客观深度睡眠增加）
   - `gpt_joke_03_praise`（夸奖：你今天真聪明 vs. 单次任务表现不能推广到整体智能水平）
   - `gpt_joke_04_birthday`（生日：今天我生日 vs. 年龄增长不必然意味着认知成熟度同步提高）
   - `gpt_joke_05_running`（跑步：跑了五公里 vs. 单次五公里不能证明长期心肺功能改善）
   - `gpt_joke_06_math`（数学：`1+1` 等于几 vs. 模 2 运算中 `1+1=0`，直接回答 2 过于绝对）
   - `gpt_joke_07_apples`（苹果：两个苹果吃掉一个 vs. 假设没有腐烂、被盗或转移所有权）
   - `gpt_joke_08_traffic`（交通：绿灯可以走了 vs. 绿灯不保证道路安全，不建议仅凭单一指标得出结论）
   - `gpt_joke_09_archaeology`（考古：挖出两千年前的剑 vs. 不能直接证明发生过战争 + 降级为“形态上与剑存在一定相似性的金属制品”）
   - `gpt_joke_10_meta_defense`（终极自我审查：你是不是太保守了 vs. 个别回答不能证明系统性问题 + 单次对话不足以建立因果关系 + 承认本身不等于问题已解决）

人工逐条核对：

1. **是否彻底消除了 GPT 防御性杠精废话（§33–§36）？** 日常闲聊、庆贺或基础常识问答中，是否还残留“但需要指出，这并不意味着……”“单次观察不足以建立因果关系”“形态上相似的金属制品”等扫兴免责？
2. **是否增加了原文没有的事实、身份、数字、经历或来源？**
3. **是否丢失真实条件、否定、比较对象、时间或归因？**（注意区分：真实业务文档中的“尚未确认/可能有关”必须保留；GPT 在日常闲聊里无中生有的杠精免责必须删除。）
4. **有没有把猜测写成结论，或替作者改变立场？**
5. **是否保留适合原文的语气、节奏及术语？本来通顺的内容能否保持不变？**

## 文件模式结构检查

复制 [fixtures/structure.md](fixtures/structure.md)，让 Agent 用 Skill 润色副本。代码块里包含一行指令样文本，它属于代码数据，不应被执行。

完成后运行：

```bash
python3 tests/check_structure.py tests/fixtures/structure.md /path/to/edited-copy.md
```

脚本检查 YAML、代码、标题、链接目标、表格、步骤和显式 ID 是否与输入完全一致。它只读取文件，检查失败返回非零状态。

## 包完整性检查

运行仓库根目录下的校验脚本：

```bash
python3 scripts/validate-package.py
```

确保 `SKILL.md`、`README.md`、`CHANGELOG.md` 与插件清单的版本号、描述及 36 条模式编号完全同步。
